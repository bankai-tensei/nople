# 性能の数字

README や紹介で使う数字の出どころです。測り方はリポジトリに入れてあり、同じ手順で測り直せます。数字を出すときは、測った環境とキャッシュの状態を一緒に書いてください。

2026-11-18 に測りました。

| | |
|---|---|
| CPU | Intel Core i7-12700H（14 コア、20 スレッド） |
| メモリ | 16 GB |
| ディスク | NVMe SSD（Phison 1 TB） |
| GPU | NVIDIA GeForce RTX 3050 Ti Laptop、Intel Iris Xe |

| Nople | `7a6dde5` の次の作業中の版、`-trimpath -ldflags "-H windowsgui -s -w"` でビルド |

## 起動

プロセスが作られてから（OS が記録したプロセスの作成時刻から）、最初の画面を描き終えるまでと、開いたもの（フォルダ、ファイル）を描き終えるまでを測りました。21 回起動し、ビルド直後の 1 回目を除いた 20 回の中央値です。

| 開いたもの | 最初の画面 | 開いたものを描くまで |
|---|---|---|
| 何も開かない（`-fresh`） | 0.10 秒（0.10〜0.14） | 0.13 秒（0.12〜0.18） |
| フォルダ（このリポジトリ） | 0.10 秒（0.09〜0.11） | 0.12 秒（0.12〜0.14） |
| Go のファイル 1 つ | 0.11 秒（0.10〜0.13） | 0.14 秒（0.14〜0.17） |

- ビルド直後の 1 回目は、最初の画面まで 0.22 秒でした。再起動の直後のような、まったく冷えた状態の起動は測っていません。
- 「開いたものを描くまで」は、フォルダの中身の読み込みや色付けを、裏で始めた直後の画面までです。Git の状態は、その後に届きます。

### 待機中

フォルダやファイルを開いたまま操作しないでいるあいだ、CPU の時間は 5 秒ごとに 3 回測って、どれも 0 ms でした。メモリはワーキングセットで約 250 MB、うち Go のヒープは約 95 MB です。

### 測り方

環境変数 `NOPLE_STARTUP_LOG` にファイルを指定して起動すると、Nople は測った値をそのファイルに書き足して終了します。

```powershell
$env:NOPLE_STARTUP_LOG = "$env:TEMP\startup.txt"
1..21 | ForEach-Object { Start-Process nople -ArgumentList '-fresh','C:\path\to\folder' -Wait }
Get-Content $env:TEMP\startup.txt
```

Windows 以外では、OS からプロセスの作成時刻を取らず、Nople のパッケージが初期化された時刻から測ります。そのため、実行ファイルを読み込む時間は入りません。

## 大きなファイル

1 行が約 80 バイトのログを、ディスクに書いてから開きました。1 つの大きさにつき 5 回開いた中央値です。

- **表示を始めるまで**: `Open` が戻るまで。先頭の 1 MB を索引にし、エディターが先頭を表示できるようになるまでです。
- **全体の索引**: 残りの行の索引ができるまで。その間も表示とスクロールと編集はできます。
- **索引のメモリ**: 索引の分だけ増えた Go のヒープです。

### Windows（ファイルは OS のキャッシュに載った状態）

Windows では、管理者の権限が無いとファイルのキャッシュを捨てられません。そのため、書いた直後で、キャッシュに載った状態の数字です。

| 大きさ | 行数 | 表示を始めるまで | 全体の索引 | 索引のメモリ |
|---|---|---|---|---|
| 100 MB | 128 万 | 2 ms 未満 | 0.03 秒 | 1.0 MB |
| 1 GB | 1,313 万 | 2 ms 未満 | 0.30 秒 | 4.4 MB |
| 10 GB | 1 億 3,130 万 | 2 ms 未満 | 8.3 秒 | 36 MB |

- Windows の Go の時計は細かい時間を測れず、1 ms 未満は 0 になります。表示を始めるまでの中央値は 0〜1.8 ms でした。
- 各大きさの 1 回目だけは、表示を始めるまで 14〜24 ms かかりました。
- 10 GB は 16 GB のメモリに全部は載らず、一部はディスクから読んでいます。

### Linux（WSL 2、キャッシュを捨てた状態と載った状態）

WSL の中の ext4 にファイルを置きました。キャッシュを捨てた状態の数字は、各回の前に `echo 3 > /proc/sys/vm/drop_caches` を実行したものです。ただし、WSL の仮想ディスクを Windows 側がキャッシュしている分は残っています。

| 大きさ | キャッシュ | 表示を始めるまで | 全体の索引 |
|---|---|---|---|
| 100 MB | 捨てた | 5.9 ms | 0.07 秒 |
| 1 GB | 捨てた | 6.1 ms | 0.65 秒 |
| 10 GB | 捨てた | 6.9 ms | 19.9 秒 |
| 100 MB | 載った | 0.9 ms | 0.02 秒 |
| 1 GB | 載った | 0.5 ms | 0.23 秒 |

### 測り方

```bash
NOPLE_MEASURE=100,1024,10240 NOPLE_MEASURE_DIR=/path/to/dir NOPLE_MEASURE_RUNS=5 go test -run TestMeasure -v -timeout 60m ./internal/bigfile
```

Linux でキャッシュを捨てながら測るには、root で `NOPLE_MEASURE_DROP='sync; echo 3 > /proc/sys/vm/drop_caches'` を足します。中身は [internal/bigfile/measure_test.go](../internal/bigfile/measure_test.go) にあります。

## ほかのエディターとの比較

同じ PC で、VS Code と Zed と比べました（2026-11-18、上と同じ PC）。大きなログを引数に渡してエディターを起動し、ファイルの中身がウィンドウに出るまでの時間と、そのあいだのメモリ（そのエディターの全プロセスのワーキングセットの合計）の最大を測っています。

| | Nople（23a4b18） | VS Code 1.133.0 | Zed 1.27.0 |
|---|---|---|---|
| 1 GB: 中身が出るまで | 0.31 秒 | 8.0 秒 | 2.1 秒 |
| 1 GB: メモリの最大 | 271 MB | 3.0 GB | 2.7 GB |
| 10 GB: 中身が出るまで | 0.35 秒 | 117 秒 | 開けない（「File is too large to load」と表示） |
| 10 GB: メモリの最大 | 392 MB | 5.8 GB | — |

- **時間の測り方**: ウィンドウを 0.03〜0.05 秒おきに画面キャプチャし、最後の表示と同じになった最初の時刻を取りました。キー入力やクリックはしていません。ウィンドウが開くアニメーションと画面の合成の遅れを含むので、上の「起動」の数字より長く出ます。3 つとも同じ方法です。
- **回数**: 1 GB は 4 回起動して、最初の 1 回を除いた 3 回の中央値です。Nople の 10 GB も同じです。VS Code と Zed の 10 GB は 1 回だけです。
- **ファイル**: 1 行約 80 バイトのログで、OS のキャッシュに載った状態です。
- **それぞれの設定**: どれも既定の設定です。
  - Nople は `nople -fresh <ファイル>` で起動し、設定は言語とテーマだけです。
  - VS Code は、空のユーザーフォルダーと拡張機能フォルダーで起動し、大きなファイルを開く前の確認だけを出ないようにしました。大きなファイルでは、VS Code 自身が色付けや折りたたみなどを切って開きます。
  - Zed は、空のユーザーフォルダーで起動しました。
- **Nople の索引**: Nople は中身を出したあとも、裏でファイル全体の索引を作っています。10 GB では、行番号の桁が増えて表示が横に動き終わるまで約 4.6 秒でした。
- **スクリプト**: 計測に使ったスクリプトと生の結果は [tools/compare/](../tools/compare/) にあります（`measure.py` と `results-2026-11-18.jsonl`）。Windows で動き、Python 3 と Pillow、numpy が要ります。使い方は `measure.py` の先頭にあります。

## 言えることと言えないこと

- 「1 GB のログが一瞬で開く」「10 GB でも開ける」は言えます。表示を始めるまでは、どの大きさでもキャッシュを捨てた状態で 7 ms 以下です。全体の索引は、ディスクを読む速さで決まります。
- 「起動 0.1 秒」は、この環境の、温まった状態の数字です。遅い機械や、再起動の直後の起動は測っていません。
- ほかのエディターとの比較は、上の 1 台の PC、キャッシュに載った状態、既定の設定での数字です。VS Code と Zed の 10 GB は 1 回しか測っていません。比べる言い方をするときは、この条件も添えてください。
